# Contribution Guide

## About the Project

This project is a Maze Path-Finding System using BFS and DFS. It contains Python code for maze generation, path finding, experiments, result collection, and performance comparison.

## How to Contribute

You can contribute by:
1. Improving BFS.
2. Improving DFS.
3. Adding new maze sizes.
4. Improving maze generation.
5. Adding new search algorithms.
6. Improving result visualization.
7. Improving documentation.
8. Fixing bugs.
9. Improving performance measurement.

## Contribution Steps

### 1. Fork the Repository
Create your own fork of the repository on GitHub.

### 2. Clone the Repository

```bash
git clone <your-repository-url>
```

### 3. Create a New Branch

```bash
git checkout -b feature-name
```

### 4. Make Your Changes

Modify the required Python files or documentation. Make sure existing BFS and DFS functionality continues to work.

### 5. Test Your Changes

Check:
- Maze generation
- BFS path finding
- DFS path finding
- Path length
- Nodes expanded
- Execution time
- Result generation

### 6. Commit Your Changes

```bash
git add .
git commit -m "Describe your changes"
```

### 7. Push Your Branch

```bash
git push origin feature-name
```

### 8. Create a Pull Request

Open GitHub and create a Pull Request from your branch to the main repository.

Explain:
- What you changed
- Why you changed it
- How you tested it

## Testing Guidelines

Before submitting:
- Make sure the program runs without errors.
- Check that BFS returns the expected shortest path.
- Check that DFS works within the depth limit.
- Make sure existing functions still work.
- Check that results are generated correctly.
- Keep new code easy to understand.

## Coding Guidelines

- Use clear variable and function names.
- Keep functions small and focused.
- Add comments where necessary.
- Avoid unnecessary changes.
- Follow the existing project structure.

## Good First Contributions

Beginners can start by:
- Improving README documentation.
- Adding comments.
- Improving output messages.
- Adding simple visualizations.
- Testing different maze sizes.
- Fixing small bugs.
